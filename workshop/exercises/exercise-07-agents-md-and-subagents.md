## The AGENTS.md anti-pattern

Research from ETH Zurich's AGENTBENCH found that LLM-generated AGENTS.md files (auto-generated by AI) produced:

- **−2% task correctness**
- **+20–23% token consumption**

> More instructions ≠ better behaviour. Every sentence in AGENTS.md is paid on every agent turn. Noise costs money AND degrades quality.

---

## Part A — The noise vs signal audit

### What belongs in AGENTS.md

| Entry type | Keep? | Example |
|-----------|-------|---------|
| Non-obvious commands | ✅ Keep | `Use uv, not pip` |
| Infra-specific gate | ✅ Keep | `Deploy requires VPN connection` |
| Convention agent can't infer | ✅ Keep | `Export as named; no default exports` |
| Surprising project constraint | ✅ Keep | `src/utils/__tests__ — not src/__tests__` |
| Observable fact | ❌ Remove | `This is a TypeScript project` |
| Directory listing | ❌ Remove | `Components are in src/components/` |
| Boilerplate reminder | ❌ Remove | `Always write clean, maintainable code` |
| Stack description | ❌ Remove | `We use React and Tailwind CSS` |

**Rule:** Every line in AGENTS.md costs tokens on every agent turn. If a line only tells the agent what it would already discover, it is pure waste.

## Part B — Create AGENTS.md for the future-you-simulator

Create `AGENTS.md` at `future-you-simulator/AGENTS.md`:

```markdown
# Agent context — future-you-simulator

## Commands
- Install: `npm install`
- Dev: `npm run dev` → http://localhost:5173
- Build: `npm run build`
- Lint: `npm run lint`
- Tests: `npm test` (Vitest)

## Non-obvious rules
- State: all state via src/store/useStore.ts (Zustand + persist). Never prop-drill.

- Animation: Framer Motion (already installed). Use motion.div for entry animations.
- Animations DO NOT run in Vitest — don't test for them.

## Surprising constraints
- No new npm packages without explicit approval.
- recharts version must stay pinned (breaking changes in v3).
```

## Part E — Subagent context isolation

### The context accumulation problem

Without subagents, a 30-turn agent session reading 5 files per turn:
```
30 turns × 5 files × ~1,000 tokens/file = 150,000 tokens for file context alone
```

### Subagent pattern

The main agent stays lightweight. Sub-tasks are offloaded to fresh subagent instances.

```
Main agent (3 files loaded) → delegates "analyse LifeTimeline" to subagent
Subagent (starts fresh) → reads 5 LifeTimeline files → returns summary
Main agent (receives ~200t summary, never read those 5 files)
= 5,000 tokens vs 15,000 tokens for the same information
= 3× saving per delegation
```

### Add subagent support to your component-builder agent

Update `.github/agents/component-builder.agent.md` (from Exercise 05):

```markdown
---
name: component-builder
description: Builds a single new React component from a spec. Isolated context.
tools:
  - read_file
  - create_file
---
You build one React component per invocation. Context is strictly scoped.

Inner-loop constraints:
- maxTurns: 10
- acceptanceCriteria: component renders without TypeScript errors
- Read only files listed in the task spec
- Stop as soon as acceptanceCriteria is met
```

> **`maxTurns`** prevents runaway agent loops. Without it, an agent can exceed 50 turns on a simple task.
